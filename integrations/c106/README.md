# C106 demand-capture recipes

These recipes expose narrow, permission-first demand surfaces for the
BRAINIALL diarized transcription skill. They deliberately stop at a safe
fixture, an owned CTA, or an explicit partner gate. A view, pull, install,
discussion, or marketplace listing is not a buyer and is never counted as
revenue.

## Routes

- `linkedin-page-newsletter.md` — corporate editorial route for content and accessibility teams.
- `community-permission.md` — Reddit and Indie Hackers listening rules.
- `medium-publication.md` — publication submission and attribution checklist.
- `github-discussions.md` — maintainer opt-in fixture for caption QA.
- `dockerhub-worker.md` — reproducible worker image without secrets.
- `rapidapi-provider.md` — narrow PT-BR API contract and provider gate.
- `storefront-preflight.md` — Firefox, Edge, F-Droid, and Apple review gates.

## Non-negotiable measurement

Record `route -> tenant/buyer hash -> first value -> checkout -> payment ->
payout -> bank reconciliation`. Do not infer payer identity from a pull,
download, subscriber, referral click, or marketplace statistic.
